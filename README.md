# Saved To Be Sent Mission Outreach: website

The public website of **Saved To Be Sent Mission Outreach (STS)**. Visitors can:

- give: bank transfer, Paystack, Stripe or crypto, then log the gift for a personal thank-you email
- become a monthly partner
- register for the **Missionaries Conference 2027**. Each person gets a seat number, a bed number and meal tickets on a printable invoice.
- join the April outreach, apply for missionary training, or send a prayer request

The site is **static**: plain HTML, CSS and JavaScript, with no server to run or pay for. Forms are delivered by email through [FormSubmit](https://formsubmit.co). An optional Google Sheet backend gives you a shared registration list (see [`backend/README.md`](backend/README.md)).

> Before going live, work through **[docs/LAUNCH_CHECKLIST.md](docs/LAUNCH_CHECKLIST.md)**.

## Run it on your computer

You need [Node.js](https://nodejs.org) 20 or newer.

```bash
npm install          # once
npm run serve        # then open http://localhost:8080
```

Opening `index.html` by double-clicking also works, but `content.json` cannot load that way, so the built-in content shows.

## Deploying

Upload the whole folder (except `node_modules/`, `tests/` and `src/`) to any static host: GitHub Pages, Netlify, Cloudflare Pages, Vercel or cPanel. All of them are free at this size. There is no build step on the server: `assets/css/tailwind.css` is already built and committed.

With **GitHub Pages**: Settings > Pages > Deploy from a branch > `main` / root. Every push publishes the site.

## Publishing content (admin)

The admin backend lives at `https://your-site/#sts-office-7k29`. Change that address in `config.js`.

1. Sign in, then make your changes: numbers, bank details, catalog, events, gallery, videos, map, settings. A yellow **DRAFT PREVIEW** badge shows that only your browser sees them.
2. In section **0. Publish Your Changes**, press **Download content.json**.
3. Upload that file next to `index.html` and replace the old one. On GitHub, open `content.json`, then **Add file > Upload files**, then commit.
4. When the new file is live, press **Discard draft**. You now see exactly what visitors see.

Why it works this way: the old version saved admin edits only in the admin's own browser, so visitors never saw them. `content.json` is the one copy everyone loads, and on GitHub every change to it is kept in the history.

Tips:
- Prefer **picture links** (or images uploaded to `assets/img/`) over uploading photos in the admin. Uploaded photos are stored inside `content.json`, which makes it larger and the site slower on mobile data. The backend shows the current size.
- **Import content.json** loads a file as a draft, for example to continue editing on another computer.

## Settings (`assets/js/config.js`)

| Setting | What it does |
| --- | --- |
| `receiverEmail` | Inbox for every form. FormSubmit sends a one-time activation email the first time. |
| `testMode` | Shows a TEST RUN badge and allows temporary test seat numbers. **Set to `false` at launch.** |
| `sheetUrl`, `sheetViewUrl` | Google Sheet backend (optional, recommended). See `backend/README.md`. |
| `ngnPerUsd` | Exchange rate used everywhere a Naira amount is shown. |
| `conference`, `aprilOutreach` | Event dates in Nigerian time (WAT), used by the countdowns. |
| `admin` | Password check for the admin backend (see below). |
| `welcomePopupEveryDays` | How often the welcome popup may appear for the same visitor. |

### Changing the admin password

```bash
node scripts/hash-password.mjs
```

Type the new password (at least 12 characters), then paste the printed `admin` block into `config.js`. The password itself is never stored.

> The admin login keeps casual visitors out of the editing screen. It is not a security boundary: everything it edits is a draft in your own browser, and nothing reaches visitors until you upload `content.json` to the host. The things that need real protection (seat numbers, resetting counters, the registration list) are guarded by the Google Sheet backend.

## Development

```bash
npm run watch:css    # rebuild Tailwind while you edit index.html / app.js
npm test             # backend + browser tests (headless Chromium)
npm run check        # rebuild CSS, confirm it is committed, run tests
```

- Tailwind is compiled ahead of time (`tailwind.config.js`). If you use a new Tailwind class, run `npm run build:css` and commit `assets/css/tailwind.css`.
- Anything inserted into the page from content or forms goes through `esc()` and `safeImg()` in `app.js`. Keep it that way.
- The tests mock every outside service (CDNs, FormSubmit, counters, Apps Script), so they run offline and never send email.
